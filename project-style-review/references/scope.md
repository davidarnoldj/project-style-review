# Local scope and coverage

Run the bundled helper with Python 3.9 or later. Resolve its path from the installed skill directory. Use quoted literal arguments and keep output in the tool response.

- List eligible files with `python3 -I -B <skill-dir>/scripts/scope.py ROOT [PATH ...]`. A path can be a file or subdirectory relative to ROOT. To review a single file, use its parent as ROOT. For a baseline, select nearby eligible files in that folder and keep findings on the requested files.
- Read selected material with `python3 -I -B <skill-dir>/scripts/scope.py --read ROOT FILE ...`. Each JSON record contains file text with a source line number and tab before each line. Use those numbers to verify excerpts. Read the applicable `AGENTS.md`, `AGENTS.override.md` or `CLAUDE.md`, then choose representative neighbours such as a contributor guide, a glossary, a sibling implementation or locale. Inherit any applicable instructions the client already loaded. Keep independent searches within the agreed scope.
- For current changes use `--changes` on the listing. Then use `--changes --patch ROOT FILE ...` for separate staged (HEAD to index), unstaged (index to file) and untracked (new file) patches. Use ordinary `--read` for surrounding current text. For an explicitly named base use `--base REV` in place of `--changes`. It adds the direct REV-to-HEAD comparison. For index or historical findings label the version and use that patch's line numbers. For removals use the old line. If the working tree already resolves a staged issue, say so and leave the index untouched. Keep findings on changed material and use unchanged code as evidence.
- For an explicit delivery check use `--read --delivery ROOT FILE ...` with the agreed file list. This permits reading a generated header in a specified deliverable. Other exclusions still apply.
- The manifest gives eligible files, a listing cap, counts of skipped entries and selections without eligible matches. A skipped directory counts as one entry regardless of its contents. Read a targeted subdirectory or use a larger `--limit` if the first listing omits relevant paths. Report files you actually reviewed rather than treating the inventory as a completed review. Use the skip summary for excluded material without opening those files.

Git mode uses Git's standard excludes for untracked files, including nested `.gitignore`, local excludes and configured global excludes. Tracked files remain in scope under Git's normal semantics, subject to the helper's exclusions. The working-tree comparison disables external diffs, text converters, configured clean/process filters, fsmonitor and partial-clone fetching. Patches compare decoded lines. They do not show newline-only differences and may show extra differences when Git conversion or custom filters are configured. Submodule contents are out of scope unless reviewed as their own working tree.

In ordinary folders the helper applies nested `.gitignore` and `.ignore` rules within ROOT. It supports anchoring, directory rules, negation, escaping, wildcards and character ranges. It prunes ignored parent directories, as Git does. Unsupported patterns such as POSIX character classes or unreadable rule files cause the affected subtree to be skipped and counted. Git is optional in ordinary folders. The helper never initialises a repository there.

The helper skips symlinks, common dependency and build paths, lockfiles, recognised generated headers and names, known secret paths and some common credential patterns, binary or undecodable text, and files above 192 KiB. Secret checks are heuristic. Stop reading or quoting if you encounter credentials that the helper did not recognise. Extend or narrow selection according to project-specific exclusions. If the helper is unavailable, use client file tools with the same safeguards. In Git mode, use read-only commands with optional locks, external filters and fetches disabled, or report any comparison you could not safely inspect.
